# Kirby Collection Manager — LLM reference

Kirby CMS plugin (`shallowred/collection-manager`) for AJAX collection
listings: search, taxonomy filters (single or multi-select), visitor-facing
sorting, pagination. Server-rendered snippets enhanced with htmx; fully
functional without JavaScript. Multiple independent instances per page.

## Architecture

- `classes/CollectionController.php` — the single pipeline. `handle($page, $config)`
  builds a `CollectionQuery` (search → filter → sort → paginate), renders the
  component snippets, and either returns template data or, for htmx fragment
  requests, echoes the fragment and exits.
- `classes/Query/CollectionQuery.php` — fluent query over a Kirby collection.
  Multi-value filters match comma-separated fields. `paginate()` clamps the
  requested page into the valid range.
- `classes/Url/UrlBuilder.php` — builds page URLs preserving only the params
  owned by the instance (search, sort, filters, pagination). Unknown query
  params are never reflected.
- `controllers/collection-item.php` — snippet controller preparing data for
  the default item card (requires lukaskleinschmidt/kirby-snippet-controller).
- `snippets/` — wrapper + components (search, filters, sorting, pagination,
  indicator, items, item). All overridable via config `snippets` map or by
  shadowing the snippet name in site/snippets.

## Request cycle

1. Controller call: `CollectionController::handle($page, $config)` reads
   `q` (search), taxonomy params, `sort`, and the pagination param via
   Kirby's `get()`.
2. Instance identity: `instanceId = 'cm-' + paginationParam`. The wrapper
   renders `<div id="{instanceId}"><div id="{instanceId}-content">…`.
3. htmx controls target `#{instanceId}-content`. The server detects fragment
   requests by comparing the `HX-Target` header to `{instanceId}-content`
   (legacy `?htmx={instanceId}` still accepted). Response: the inner fragment
   (search, filters, sorting, items, pagination) with `Vary: HX-Target`.
4. URLs pushed to the address bar are the clean page URLs; reloading any URL
   renders the full page.

## Config essentials (all optional)

```php
[
  'collection' => $pages,               // Kirby collection object or 'children'
  'search' => ['fields' => [...], 'param' => 'q'],
  'taxonomies' => [['param','field','label','multiple' => bool]],
  'pagination' => ['limit' => 10, 'param' => 'p', 'range' => 5],
  'sorting' => ['default' => 'date', 'direction' => 'desc',
                'options' => ['date' => 'Label', 'title:asc' => 'Label'],
                'param' => 'sort'],
  'enableSearch'|'enableFilters'|'enableSorting'|'enableIndicator'|
  'enablePagination'|'enableJs' => bool,
  'snippets' => ['item' => 'my-card', ...],
]
```

- Sorting UI renders only when `enableSorting` and >1 `sorting.options`;
  requested sort keys are whitelisted against the options.
- Multi-instance pages: give each instance a distinct `pagination.param`.
- Search term capped at 100 chars. Filter options are computed from the full
  configured collection (`pluck(field, ',')`).

## Template usage

```php
// controller
return CollectionController::handle($page, $config);
// template
snippet('collection-manager', compact('collection', 'config', 'snippets'));
```

`$snippets` is an array of rendered HTML: search, filters, sorting,
pagination, indicator, items — usable individually for custom layouts.

## Testing

- Playwright e2e in `tests/e2e/`, run against `demo/` (needs a Kirby core in
  `demo/kirby`, not versioned): `npm test`.
- `composer lint` (phpcs, PSR-12 with 2-space indent; template snippets are
  excluded from the indent sniffs).
